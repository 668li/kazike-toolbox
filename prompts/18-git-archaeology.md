# Git 考古：历史包袱鉴定

> 来源：用户投稿（2026-11-19）· 原始表述：「深入分析整个代码库的Git历史、关键PR和架构演变过程。找出哪些设计是有意为之，哪些是历史遗留，哪些是为了解决已经不存在的问题而引入的。识别可以安全移除的历史包袱。」
> 解决的问题：代码库里有些东西没人敢动，也没人说得清为什么存在。

## 什么时候用

接手老项目、准备大重构、或者想确认某块代码/某个抽象能不能删。

## Prompt

```
请分析这个代码库：【仓库路径】。范围：【全库 / 某个模块 / 某段历史】。

先读 Git 历史、关键 commit 和 PR/合并记录，还原架构演变过程，再回答：
1. 当前设计里哪些是有意为之？当时的约束是什么？
2. 哪些是历史遗留？
3. 哪些是为了解决一个已经不存在的问题而引入的？
4. 哪些模块的复杂度找不到对应的业务价值？
5. 哪些可以安全移除？哪些看起来废弃、实际还有隐性依赖？

每条结论都要给证据（commit hash、PR 编号、文件与行号、blame 结果），证据不足的标「推测」。不要凭代码风格猜历史。

最后按「移除收益 × 风险」排序，给出 3 个最值得清理的历史包袱，每个附一个验证「真的没人用」的方法。
```

## 执行要点

- 必须真跑 `git log` / `git blame` / 查 PR，**不许凭目录结构编故事**。
- 证据分级：commit/PR 直接证明 > 代码注释 > 命名推断。
- 区分「**丑但有用**」和「**真包袱**」：丑不是删除理由，无价值才是。
- 删除建议必须带**验证方法**：全库引用搜索、灰度开关、观察期。
- 不要建议「一次性大重写」，那不是考古结论。
