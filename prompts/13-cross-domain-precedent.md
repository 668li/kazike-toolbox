# 跨领域母题检索

> 来源：用户投稿（2026-11-19）· 原始表述：「我的想法或目前存在的问题是否是其他领域经典问题的变体，有无成熟的解决方案，请进行跨领域的广度搜索核实这一点」
> 解决的问题：怕自己在重新发明轮子，或把一个早就有标准答案的问题当成新问题。

## 什么时候用

你有一个想法或卡点，但说不清它属于哪一类问题，想先确认「这是不是某个领域早就研究透的老问题、有没有现成解法」。
如果问题结构已经很清楚、只想借别的行业的机制，直接用 `08-cross-domain-borrowing.md`，不用走这条。

## Prompt

```
我的想法/问题是：【用自己的话描述，包含背景、当前做法、具体卡点】。

请先剥掉行业术语，把它抽象成一句不含本行业名词的问题描述。然后做跨领域广度检索，核实：
1. 这是不是某个领域已经反复出现过的经典问题？如果有，它在该领域的标准叫法是什么（某个悖论、困境、定理、模式或已有术语）？
2. 至少 5 个彼此距离较远的领域里，有没有结构相同的问题？它们各自形成了什么成熟解法？
3. 这些解法的适用前提和失效边界是什么？
4. 与我的问题相比，哪些地方结构同构、哪些关键差异会让别人的解法在我这里失效？

请给出信息来源，并明确区分「确实有经典命名/成熟解法」和「只是看起来像」。找不到就直说找不到，不要硬凑类比。

最后按「迁移成本 × 预期收益 × 失效风险」排序，给我 3 个最值得采用的成熟方案，并指出哪一个最适合先试、第一步做什么。
```

## 执行要点

- **必须真检索**，不能凭记忆报菜名。每个「经典问题」都要有一手来源和提出者/年代。
- **「有标准名字」和「结构相似」是两回事**。前者是已命名的问题类，后者只是类比，必须分开写。
- 领域要**彼此距离远**，三个相邻行业不算「跨领域」。
- **失效边界必写**。不写边界的类比都是廉价类比。
- 结尾必须落到可执行的第一步，不停在「可以参考」。
