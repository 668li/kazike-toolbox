# 需求真伪诊断

> 来源：用户投稿（2026-11-19）· 原始表述：「不要默认我提出的问题定义就是正确的。你先分析我真正想解决的底层需求，判断我有没有把症状误认为原因、把手段误认为目标。如果存在更值得解决的问题，直接指出来」
> 解决的问题：带着一个方案或问题定义来，但定义本身就是错的，越努力越偏。

## 什么时候用

用户开口就是「我想做/加/改一个 X」，却说不清为什么；或者描述里全是情绪和现象，没有可验证的目标。

## Prompt

```
先不要接受我对问题的定义。我说的是：【我的问题描述，或我想做的改动】。

请分析：
1. 我描述的是一个症状、一个原因、一个手段，还是一个目标？
2. 我真正想满足的底层需求是什么？至少给出 2 种合理解释，并说明各自的证据。
3. 我把什么手段当成了目标？把什么症状当成了原因？
4. 如果照我原话执行，最可能出现什么「做了但没用」的结果？
5. 是否存在更值得解决的问题？如果有，直接指出来，并说明为什么它比原问题更值得解决；如果没有，也明确说原定义成立。

最后给我一个重新表述的问题，写清「谁、在什么场景下、要达成什么、用什么衡量」；等我确认后再谈方案。
```

## 执行要点

- 必须明确点出原话属于**症状 / 原因 / 手段 / 目标**中的哪一类，不要含糊。
- 至少给 **2 种底层需求解释**，不要只换一个说法复述用户的话。
- **不要为了显得深刻而否定**。原定义成立时就说成立，这同样是结论。
- 最后的问题陈述必须**可衡量**，否则等于没重写。
- 用户确认新问题前，不给方案。
